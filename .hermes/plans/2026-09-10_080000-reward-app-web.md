# Reward App Web Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Build a local-first, zero-mandatory-cost MVP for a rewards/earning web application with a React/Vite frontend, Express/TypeScript API, PostgreSQL, Docker Compose, demo-only rewards, and production-ready extension points.

**Architecture:** A modular monolith Express/TypeScript API serves the React SPA, stores all financial state in PostgreSQL, and exposes only server-authoritative reward, wallet, referral, withdrawal, and audit operations. The frontend uses React Router and a mobile-first design. Docker Compose supplies PostgreSQL for local development; no paid services are required.

**Tech Stack:** React 18 + TypeScript + Vite, Express + TypeScript, PostgreSQL, Prisma ORM, JWT bearer auth, bcrypt, Zod, Helmet, CORS, and Jest/Vitest-style Node tests. The existing Flutter project at `reward_app` is preserved and not overwritten.

## Risks and tradeoffs

- Free hosting tiers change; the local Docker/PostgreSQL path is the guaranteed baseline.
- Demo rewards and withdrawals are simulation-only and must never be represented as real payouts.
- JWT refresh tokens are stored server-side in PostgreSQL and are rotated on each refresh.
- The initial fraud system is heuristic and requires human review for consequential actions.
- Legal/compliance review is required before accepting real money or making real payouts.
