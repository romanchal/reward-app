1. What this is & what's inside

A rewards web app with a wallet, tasks, missions, referrals, withdrawals, admin console, and an audit trail. Demo mode by default. Real money only turns on when you flip the keys.

What was built

AreaWhat it does
User appSign in, home dashboard, earn tasks, missions, rewards catalogue, leaderboard, profile, withdrawals.
Admin consoleUsers (ban/restore), tasks (create/disable), withdrawals (approve/reject/bulk), fraud review, manual payments, settings.
Backend APIExpress + Postgres + Prisma. JWT auth, refresh cookies, rate limits, field encryption, audit log, Razorpay payouts, webhook, idempotent money moves.
InfraDocker Compose, healthchecks, GitHub Actions CI, Sentry hooks everywhere, Postman collection.

What was NOT built (on purpose)

  • Password reset flow — add when a user forgets a password.
  • Two-factor auth — add when the admin console is public.
  • File-upload for manual-payment proof — stores a URL for now, point at any object storage later.
  • Server-rendered PDF receipts — HTML + browser print covers it.
  • KYC — depends on the market you serve.

2. Where the project stands today

The code is done. The live service is not. Here's the honest split.

Code: 100%

Code shipped
100%

Operations & setup: about 20%

Live-ready
20%

What that 20% means: the code builds, runs, and self-tests on docker compose up in demo mode. The remaining 80% is paperwork and account creation: Sentry, Razorpay, a domain, a server, TLS, backups.

Translation: you can show the app to someone today. You cannot take a real rupee until Steps 2–7 of this book are done.

3. The seven steps to go live

Do them in order. Do not skip. Each step unlocks the next.

1

Fresh install on a server

Pick a server (DigitalOcean, Hetzner, your laptop). Install Docker. Clone the repo. Boot it.

2

Generate the secrets

Random keys for JWT, refresh, and encryption. One shell command does all three.

3

Create a Sentry project

Paste two DSNs into .env. Now you'll know when the app breaks before users tell you.

4

Create a Razorpay account

Get API keys. Get the virtual account number. Set up the webhook. Paste four values into .env.

5

Buy a domain & put HTTPS in front

Point two subdomains at your server. Install Caddy. HTTPS is automatic from there.

6

Change the default admin password & smoke-test

Log in. Change the admin password. Run through: register → earn → withdraw → admin approve.

7

Backups & monitoring

Daily DB dump to encrypted storage. Uptime monitor pinging /api/health. Done.

Step 1 — Fresh install on a server

Any Linux box with Docker will do. 2 CPU, 2 GB RAM is enough to start.

Shopping list

  • A VPS (DigitalOcean "Basic" droplet, Hetzner CX22, AWS Lightsail — any of them).
  • SSH access to it.
  • A GitHub account that can read the repo.

Commands

ssh root@your-server-ip
apt update && apt install -y docker.io docker-compose-plugin git
git clone https://github.com/NectarScript/reward-app.git
cd reward-app
cp .env.example .env
docker compose up -d --build

Wait 5–10 minutes the first time (image pulls + build).

How to check it worked

curl http://localhost:4000/api/health
# expect: {"status":"ok","env":"development",...}
If the curl returns ok, Step 1 is done. The app is running in demo mode. You can now plug in real services.

Step 2 — Secrets you must generate

Three random values. One script generates them. Paste the output into .env.prod.

Why

  • JWT_SECRET & JWT_REFRESH_SECRET — sign the tokens that keep users signed in.
  • ENCRYPTION_KEY — encrypts personal data (like UPI handles) in the database.

Command

bash scripts/gen-secrets.sh > .env.prod

Open .env.prod and verify three lines have long random values. That's it.

Never commit .env.prod to git. It's already in .gitignore. Verify with git status before every push.

Step 3 — Sentry (error reports)

Free tier. 5 minutes. Lets you see every crash before a user complains.

What to do

  1. Sign up at sentry.io.
  2. Create a project → platform Node.js → name it reward-app-backend. Copy the DSN.
  3. Create another project → platform React → name it reward-app-web. Copy that DSN.
  4. Open .env.prod. Paste:
SENTRY_DSN=https://<backend-dsn-here>@sentry.io/...
VITE_SENTRY_DSN=https://<react-dsn-here>@sentry.io/...

Verify

After docker compose up --build, hit an invalid endpoint. Within a minute the error should appear on your Sentry dashboard.

If no DSN is set, Sentry does nothing. The app runs normally. So setting it is optional for Day 1 but recommended before Day 2.

Step 4 — Razorpay (real payouts)

This is the one big setup. One hour, lots of forms. After this you can pay users real money.

Account

  1. Sign up at razorpay.com.
  2. Activate RazorpayX / Payouts. You will submit business documents (GST, PAN, bank statement). Approval takes 1–3 business days.
  3. Fund the Razorpay virtual account from your business bank account. You pay out from this balance.

API keys

  1. Dashboard → Account & Settings → API Keys → Generate.
  2. Copy Key ID and Key Secret. The secret is shown only once.
  3. Dashboard → RazorpayX → Account Number. Copy the virtual account number (looks like 7878780080xxxxxx).

Webhook

  1. Dashboard → Webhooks → Add.
  2. URL: https://api.yourdomain.com/api/webhooks/razorpay (your production API URL).
  3. Events: payout.processed, payout.failed, payout.reversed.
  4. Set a secret (any random string). Save. Copy it.

Paste into .env.prod

RAZORPAY_KEY_ID=rzp_live_xxx
RAZORPAY_KEY_SECRET=xxx
RAZORPAY_ACCOUNT_NUMBER=7878780080xxxxxx
RAZORPAY_WEBHOOK_SECRET=the-random-string-you-set
Test with keys first. Razorpay has Test Mode keys (rzp_test_...). Use those while you set up the webhook. Switch to rzp_live_ only after end-to-end testing.

Step 5 — A domain and HTTPS

Your users won't type an IP address. You need a domain. HTTPS is free with Caddy.

Buy a domain

Any registrar: Namecheap, Cloudflare, Porkbun. Buy yourbrand.com.

Point DNS at your server

In the registrar's DNS panel, add three records (A records) pointing at your server's IP:

NameTypeValue
appAyour.server.ip.address
adminAyour.server.ip.address
apiAyour.server.ip.address

DNS takes 5 minutes to 24 hours to propagate.

Install Caddy on the server

apt install -y caddy

Edit /etc/caddy/Caddyfile

app.yourbrand.com {
  reverse_proxy 127.0.0.1:5173
}

admin.yourbrand.com {
  reverse_proxy 127.0.0.1:5174
}

api.yourbrand.com {
  reverse_proxy 127.0.0.1:4000
}
systemctl restart caddy

Caddy automatically gets a Let's Encrypt certificate. HTTPS is now live.

Tell the app its public URLs

In .env.prod:

FRONTEND_ORIGIN=https://app.yourbrand.com
ADMIN_ORIGIN=https://admin.yourbrand.com

Switch to the production compose file

docker compose \
  --env-file .env.prod \
  -f docker-compose.yml \
  -f docker-compose.prod.yml \
  up -d --build

Step 6 — First admin + smoke test

Change the default password. Make one of everything. Watch it work.

Seed demo data (optional)

docker compose exec backend node dist/scripts/seed.js

Creates 20 demo users + admin@example.com / password123.

Change this admin password immediately. Everyone who reads this book knows it. Until a password-change endpoint ships, update it directly: 
docker compose exec postgres psql -U reward_app -d reward_app -c \
"UPDATE \"User\" SET \"passwordHash\" = '<bcrypt-hash-here>' WHERE email = 'admin@example.com';"
Generate a bcrypt hash with: 
docker compose exec backend node -e \
"console.log(require('bcryptjs').hashSync('your-new-password', 12))"

Smoke test

  1. Open https://app.yourbrand.com. Register a new user.
  2. Complete 1 task. Check the wallet balance went up.
  3. Request a withdrawal (any small amount).
  4. Open https://admin.yourbrand.com, log in as admin.
  5. Approve the withdrawal. If Razorpay keys are live, a real payout fires.
  6. Create a second admin user. Try the Manual Payment flow (maker-checker).

Step 7 — Backups & monitoring

The boring step. It's what separates a toy from a service.

Daily database backup

On the server, add this to crontab -e:

0 3 * * * cd /root/reward-app && \
  docker compose exec -T postgres pg_dump -U reward_app reward_app | \
  gzip > /var/backups/reward-$(date +\%F).sql.gz

Then push /var/backups to S3 / Backblaze / rsync.net nightly.

Uptime monitor

Sign up for UptimeRobot (free). Add a monitor:

  • URL: https://api.yourbrand.com/api/health
  • Interval: 5 minutes
  • Alert: your email + phone (SMS)

What else to watch for

  • Disk space on the server. Postgres grows. Set an alert at 80%.
  • Sentry errors — set a weekly digest email.
  • Razorpay balance — add a reminder to top up.

Common problems & fixes

"Cannot connect to Docker daemon"

Docker Desktop isn't running (or you're on Linux without the service enabled). Start Docker Desktop and wait for green "Engine running". On Linux: systemctl start docker.

"Repository not found" when pulling

Your GitHub login doesn't have access. Run gh auth switch --user NectarScript to switch accounts, or ask the owner to add you as a collaborator.

"Port 4000 (or 5173, 5174) already in use"

Something else is bound to that port. Find it: lsof -i :4000. Stop it, or change the port mapping in docker-compose.yml.

Admin login says "Admin access required"

You registered a normal user. Log in with admin@example.com (after seeding), or make an existing user admin:

docker compose exec postgres psql -U reward_app -d reward_app -c \
"UPDATE \"User\" SET role='ADMIN' WHERE email='you@example.com';"

Withdrawal approval says "Razorpay not configured"

You set Razorpay keys but one of them is wrong. Double-check all four variables in .env.prod. Restart the backend: docker compose restart backend.

Razorpay webhook says "Invalid signature"

The RAZORPAY_WEBHOOK_SECRET in .env.prod doesn't match the one you set in Razorpay dashboard. They must be identical.

"Insufficient balance" when a user tries to withdraw

Expected. User needs wallet.balance ≥ amount. For demo testing, as admin create a Manual Payment to top up a user, approve it (from a second admin), and that user can now withdraw.

Final checklist

Tick every box before telling anyone the app is live.

  • Server up, docker compose ps shows all services healthy
  • Fresh JWT_SECRET, JWT_REFRESH_SECRET, ENCRYPTION_KEY in .env.prod
  • .env.prod is NOT in git (git status clean)
  • Sentry DSN set — test error visible in Sentry dashboard
  • Razorpay keys set — one test payout succeeded in Razorpay dashboard
  • Webhook configured — simulated payout flipped a withdrawal to COMPLETED
  • Domain purchased, DNS pointed at server
  • Caddy running, both subdomains load over HTTPS (padlock in browser)
  • Default admin password rotated — original password123 no longer works
  • Second admin user created so maker-checker works
  • GitHub repo is private
  • Daily DB backup cron added — one restore drill done
  • UptimeRobot (or similar) pinging /api/health
  • Legal/compliance review done if real payouts enabled
  • You know how to roll back: git revert <sha> && docker compose up --build
