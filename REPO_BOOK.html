6. Suggested order of operations

If this is your first time, do them in this order. Each step gates the next.

  1. Clone, boot in demo mode. docker compose up --build. Verify /api/health returns ok.
  2. Seed demo data. docker compose exec backend node dist/scripts/seed.js. Log in as demo1@example.com and admin@example.com (both password123).
  3. Rotate the admin password immediately. See OPERATOR §10.
  4. Create the second admin so maker-checker works for Manual Payments.
  5. Run through the smoke test: register a new user → earn a task → request a withdrawal → approve as admin → create a manual payment → approve as the other admin → open the receipt.
  6. Sign up for Sentry, paste both DSNs, rebuild. Trigger a test 500 and confirm it shows up in Sentry.
  7. Buy a domain + Caddy + DNS. HTTPS live.
  8. Switch to the prod compose overlay with real secrets.
  9. Razorpay setup (KYC in parallel). Test with rzp_test_ keys first. Confirm a test payout flips a withdrawal to COMPLETED via the webhook.
  10. Backups + uptime monitor.
  11. Switch to rzp_live_ keys only after full test coverage.
  12. Add password reset + 2FA for admin before telling anyone the app is public.

Final checklist

  • Server up, docker compose ps all healthy
  • Fresh JWT / refresh / encryption key in .env.prod, not dev defaults
  • .env.prod NOT in git
  • Sentry DSNs set, test exception visible
  • Razorpay test keys set, test payout succeeded, webhook flipped a withdrawal
  • Domain purchased, DNS pointed, Caddy serves HTTPS (padlock)
  • Default admin password rotated
  • Second admin user exists
  • GitHub repo private
  • Daily DB backup cron added, one restore drill done
  • UptimeRobot pinging /api/health
  • Password reset flow added before public launch
  • 2FA on admin before public launch
  • Legal / compliance review signed off before live payouts
  • Switched to rzp_live_ keys
